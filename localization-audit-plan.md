# Localization Audit & Cleanup Plan

## Overview

**Goal:** Audit and refine the 5 ARB localization files (`lib/l10n/app_{en,de,ar,fr,es}.arb`) to eliminate duplicate keys, remove non-translatable strings, fix broken ICU plural expressions, and align with Flutter localization best practices.

**Scope:** `lib/l10n/app_*.arb` (template + 4 translations) and related call sites in `lib/` Dart code.

**Approach:** Four focused sub-tasks applied to all five ARB files simultaneously. The template file `app_en.arb` drives every change; translations follow in lock-step. Generated Dart files (`app_localizations*.dart`) are **not** edited by hand — they are regenerated by running `flutter gen-l10n` after each sub-task.

**Out of scope:** Re-translating strings, changing `l10n.yaml` or `pubspec.yaml`, modifying `StringConstants` in `constants.dart` (already clean).

## Sub-Task 1 — Remove Exact-Duplicate Keys (same English value, different key)

**Status:** [ ] pending

### Intent
Three pairs of keys exist where both keys carry an identical (or semantically-equivalent) English value and are used in **different** call sites. Keeping both creates translation maintenance burden: translators must translate the same sentence twice, and de-sync is inevitable.

The survivor key is chosen by semantic precision; the redundant key is removed from all ARB files and its **one** Dart call site is updated to use the survivor.

### Issues Found

| Redundant key (remove) | Survivor key (keep) | Shared English value | Call site to update |
|---|---|---|---|
| `debugDescription` | `enableDebugLogging` | `"Enable debug logging"` | No live Dart call site for `debugDescription` |
| `invalidFileError` | `invalidFileFormat` | `"Invalid file: {error}"` | No live Dart call site for `invalidFileError` (only generated file) |
| `enablePinLockFirst` | `enablePinLockFirstBiometric` | Similar "enable PIN lock first" messages | No live Dart call site for `enablePinLockFirst` |
| `importedProfiles` | `successfullyImportedProfiles` | Count-of-profiles-imported message | `importedProfiles` has no live call site; `successfullyImportedProfiles` is the one used |
| `tunnelWithValue` | `tunnelLabel` | `"Tunnel: {…}"` with-value pattern | `tunnelWithValue` has no live call site |
| `interfaceLabel` | *(passthrough wrapper only)* | `"{interface}"` — a no-op passthrough | No live call site outside generated files |

> **Note on `interfaceLabel`:** The value is literally `"{interface}"` — it simply returns its own argument unchanged. This is not a translatable string; it is a formatting artifact. It should be removed and call sites should use the raw string directly. No live Dart call site was found.

### Expected Outcomes
- Six redundant ARB keys removed from all five locale files.
- Zero live call-site changes required (all redundant keys are unused in Dart code).
- `flutter gen-l10n` succeeds with no errors.

### Todo List
1. In `app_en.arb` (and all four translation ARBs), remove the following key+`@key` pairs:
   - `debugDescription` / `@debugDescription`
   - `invalidFileError` / `@invalidFileError`
   - `enablePinLockFirst` / `@enablePinLockFirst`
   - `importedProfiles` / `@importedProfiles`
   - `tunnelWithValue` / `@tunnelWithValue`
   - `interfaceLabel` / `@interfaceLabel`
2. Run `flutter gen-l10n` and confirm the build is clean.

### Relevant Context

## Sub-Task 2 — Merge Near-Duplicate Keys (same meaning, slightly different wording)

**Status:** [ ] pending

### Intent
Several pairs of keys express the same concept with only minor wording variation, and their **two** Dart call sites can be unified. Keeping both wastes translator effort and risks inconsistency.

For each pair: keep the more precise/complete key, update the one Dart file that uses the redundant key, then remove the redundant key from all ARBs.

### Issues Found

| Redundant key (remove) | Survivor key (keep) | Dart file to update |
|---|---|---|
| `allowSelfSigned` ("Allow Self-Signed Certificate") | `allowSelfSignedCertificates` ("Allow Self-Signed Certificates") | `lib/widgets/login/connection_fields_section.dart:91` |
| `selfSignedCertWarning` (long warning) | `selfSignedCertificatesWarning` (short warning) | These carry **different** content — keep both, no merge needed (see note below) |
| `rowsPerPage` ("Rows per page") | `rowsPerPageLabel` ("Rows per page: ") | `lib/screens/openvpn_instances_list_screen.dart:321` and `lib/screens/openvpn_static_keys_list_screen.dart:228` |
| `filterLabel` ("Filter: ") | `filters` ("Filters") | These serve different UI roles — keep both (see note below) |

> **Note on `selfSignedCertWarning` / `selfSignedCertificatesWarning`:** The two keys have meaningfully different lengths: the first is a full warning sentence ("Warning: Self-signed certificates are less secure. > **Note on `filterLabel` / `filters`:** `filterLabel` renders a prefix inline ("Filter: ") while `filters` is a section title. Different contexts — keep both.

### Expected Outcomes

## Sub-Task 3 — Remove Non-Translatable Strings

**Status:** [ ] pending

### Intent
Strings that embed brand names (WireGuard, OpenVPN, Tailscale), protocol acronyms used as UI labels, or UI-text that contains a brand name as a structural part of the phrase should remain in the ARB **only** if the surrounding sentence has genuine linguistic variation across locales. If the string is purely the brand name itself — acting as a section title with no translatable words — it should be hardcoded.

After reviewing each entry against all five translations, the following categories of strings are identified for removal.

### Category A — Pure brand-name section titles / labels (identical in all locales)

These keys contain *only* the brand name with no surrounding translatable text. They are already translated identically across all five locales (or nearly so). Replace with `StringConstants.*` references.

| Key | Value | Replace with |
|---|---|---|
| (none in this project) | — | — |

> After reviewing all 17 brand-name-containing keys, **none** qualify for removal under this strict criterion. Every key contains a surrounding translatable phrase (e.g., "WireGuard Logs", "Tailscale Authentication", "OpenVPN Instances"). The brand name is embedded in context. These are properly translatable strings because the surrounding words ("Logs", "Authentication", "Instances") are translated differently in each locale. No keys are removed in this category.

### Category B — `selectServerAndGenerateKeys` — Markdown heading leaked into ARB

The value is `"# Select a server and generate keys to preview configuration"` — the `#` at the start is a **Markdown heading marker** that was accidentally included in the string. This is a UI content bug, not a localization issue.

**Action:** Remove the `#` prefix from the English value and all translations. Do **not** remove the key.

### Category C — `successfullyWokenDevices` — Broken ICU plural expression

The English value uses a manual `{plural}` string parameter (`"device{plural}"`) instead of a proper ICU plural selector. This means the Dart call site manually computes `'s'` or `''` and passes it as a string:

```dart
// lib/screens/wol_screen.dart:135 — current broken usage
l10n.successfullyWokenDevices(successCount, results.length, results.length > 1 ? 's' : '')
```

This is not valid ICU format and will fail for any language where pluralization rules differ from English (Arabic, for example, has 6 plural forms).

**Action:** Rewrite the ARB entry as a proper ICU plural expression for `successCount` in **all five** locale files, then update `wol_screen.dart` to remove the manual `plural` argument.

**New English value:**
```
"Successfully woken {successCount} of {totalCount} {successCount, plural, =1{device} other{devices}}"
```

**New ARB metadata** — remove the `plural` placeholder, add `successCount` type `int`, keep `totalCount` type `int`.

The four translation files must also be updated with their locale-appropriate ICU plural forms.

### Expected Outcomes
- `#` heading marker removed from `selectServerAndGenerateKeys` in all five ARBs.
- `successfullyWokenDevices` rewritten as proper ICU plural in all five ARBs.
- `lib/screens/wol_screen.dart` updated: the call becomes `l10n.successfullyWokenDevices(successCount, results.length)` (no third argument).
- `flutter gen-l10n` succeeds with no errors.

### Todo List
1. In all five ARBs, find `"selectServerAndGenerateKeys"` and remove the leading `# ` from its value.
2. In `app_en.arb`, rewrite `successfullyWokenDevices` as:
   ```json
   "successfullyWokenDevices": "Successfully woken {successCount} of {totalCount} {successCount, plural, =1{device} other{devices}}",
   "@successfullyWokenDevices": {
     "description": "Success message showing how many devices were woken",
     "placeholders": {
       "successCount": { "type": "int", "example": "3" },
       "totalCount":   { "type": "int", "example": "5" }
     }
   }
   ```
3. Update the German, French, Spanish, and Arabic translations with locale-appropriate ICU plural forms for `successfullyWokenDevices`.
4. In `lib/screens/wol_screen.dart` line 135, remove the third argument (`results.length > 1 ? 's' : ''`) from the `successfullyWokenDevices` call.
5. Run `flutter gen-l10n` and confirm the build is clean.

### Relevant Context
- `lib/screens/wol_screen.dart:135`
- `app_en.arb:2252` (`selectServerAndGenerateKeys`)
- `app_en.arb:2481` (`successfullyWokenDevices`)
- ARB entries in all five locale files for both keys.

## Sub-Task 4 — Fix `importFailed` / `importFailedWithErrors` Near-Duplicate

**Status:** [ ] pending

### Intent
Two keys exist for import failure messages with subtly different placeholder naming (`{error}` vs `{errors}`), but their usage pattern in code is consistent: `importFailed` is used when there is a **single error string** and `importFailedWithErrors` is used when there is a **joined list of errors**. Both render as `"Import failed: <text>"`. The difference is only in the parameter name, not in the translated phrase itself — which means translators translated the same sentence twice.

The correct fix is to keep one key (`importFailed`) and update the two `importFailedWithErrors` call sites to use `importFailed` instead.

### Expected Outcomes
- `importFailedWithErrors` removed from all five ARBs.
- Two Dart call sites updated to use `importFailed`.
- `flutter gen-l10n` succeeds with no errors.

### Todo List
1. Verify the call sites:
   - `lib/screens/login_screen.dart:329` — currently calls `importFailedWithErrors(errors.join(', '))`
   - `lib/screens/settings/profile_import_export_screen.dart:129` — currently calls `importFailedWithErrors(result.errors.join(', '))`
2. Update both call sites to use `l10n.importFailed(...)` with the same argument.
3. Remove `importFailedWithErrors` / `@importFailedWithErrors` from all five ARB files.
4. Run `flutter gen-l10n` and confirm the build is clean.
